# CT_Prime 日誌批改

## 部署與設定

後端啟動時會冪等新增 `users.ct_prime BOOLEAN NOT NULL DEFAULT FALSE`，並由 `init_db` 建立
`journal_reviews`、`journal_review_images`、`journal_review_notifications`。
既有帳號一律不自動開通。部署包含後端和前端；本文件不代表已部署。

在 Railway 的 `users` 資料表找到對應 UID，將 **ct_prime** 設為 **true** 即可。
這是獨立布林欄位，不要把 `plan` 改為 CT_Prime，也不需新增啟動碼。
學生和使用批改功能的老師都需要這個標記。老師沿用既有的管理員設定：
`display_name` 有非空白內容即代表老師；不要求先發布日誌。學生名稱未設定則顯示 UID。
批改老師名單同時要求 `ct_prime=true` 與非空白的 `display_name`，並排除登入者自己。

| 資格 | 個人日誌 | 私人批改 | 公開老師日誌 | 回測、主控台等 |
| --- | --- | --- | --- | --- |
| 有效 30 天／永久，無 CT_Prime | 可用 | 不顯示、不授權 | 可用 | 沿用原權限 |
| 7 天／未啟用／過期，無 CT_Prime | 沿用原限制 | 不顯示、不授權 | 沿用原限制 | 沿用原權限 |
| 有 CT_Prime | 可用 | 可用 | 仍需有效 30 天／永久 | **完全沿用原權限** |

CT_Prime 不會改動 `plan`、`starts_at` 或 `expires_at`。未啟用帳號的主控台仍鎖定。
取消標記後，批改 API 立即拒絕存取，但保留紀錄；重新登入／重新整理後介面同步。
清空老師的 `display_name` 或關閉 `ct_prime` 後，將不再列入批改老師，也無法開啟學生作業。
取消公開日誌不影響批改資格。送交視窗每次開啟與切回網站時會重新取得老師名單。

## 操作

- 學生：「我的日誌」→「送交批改」→ 選一位老師，可填問題 → 確認送交。
- 送交時保存不可覆寫的文字與圖片快照。之後編輯或刪除個人原稿不影響該輪批改。
- 同一篇日誌有待批改／批改中的作業時，不能再送交。
- 老師：「學生作業」表格可搜尋學生 UID、名稱、標題並篩選狀態。
- 開啟作業後轉為「批改中」。可對段落／圖片留言，並寫整體建議、貼圖、設定文字顏色。
- 「儲存草稿」只儲存老師可見的內容；「送出回饋」經確認後才讓學生看到，並發送站內私人通知。
- 完成的回饋不再修改。學生回到原日誌修訂並送交同位老師，建立下一輪且保留上一輪。
- 原日誌已刪除時，學生仍可閱讀回饋，但須另建日誌才能提交新作業。
- 私人通知與狀態在頁面使用中每 20 秒檢查；送交、儲存、送出均有明確回饋。

## 資料隔離與相容性

- 每次 API 都檢查 CT_Prime 和作業參與者身分，只有學生本人與指定老師能讀取。
- 草稿建議、草稿評語與尚未送出的圖片不提供給學生；完成後只開放回饋內引用的圖片。
- 提交使用 request key 避免重試重複建立；老師儲存有版本檢查，避免多視窗互相覆寫。
- PostgreSQL 的原稿／作業列鎖序列化提交、刪除與批改寫入。
- 原本老師公開發布權限、會員日期、行情來源、掃描與評分算法沒有變更。
- 閱讀頁沿用既有圖片延遲載入與離屏釋放，避免一次解碼大量截圖。

## 驗證

`tests/test_journal_reviews.py` 涵蓋方案隔離、草稿／圖片隱私、快照保留、通知收件人、
重複提交、版本衝突、下一輪、取消權限與預設不開通的遷移。
另執行既有日誌、啟動碼、登入與排程會員回歸測試。
SQLite 測試驗證存取和資料流程，不等同 PostgreSQL 並發壓力測試。
